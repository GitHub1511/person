## 19. The ultra tier (in progress)

Two additional complexity levels, `ultra` and `mega`, are defined above `max`.  They retain the
classic body at `max` size and add **plug-in subsystems** (`embodied_human/ux_*.py`) that execute
alongside it through a shared bus (`embodied_human/ultra.py`).  A subsystem can be written, tested
and benchmarked without the simulator (`ultra.SyntheticBus`).  Each subsystem declares its own sizes
per level, its update rate, and its memory and wall-time budgets, and is checked by
`tools/ultra_bench.py`.  The tool `tools/simlock.py` prevents concurrent workers from exhausting
random-access memory (RAM).  An optional wall-clock governor lengthens the update periods when the
machine is under load.  Conventions are documented in `docs/ultra/CONVENTIONS.md`.

**Measured baseline (2026-10-07, `python tools/scale_complexity.py --measure base rich extreme`,
output recorded in `out/measure_baseline.txt`):**

| | base | rich | extreme |
|---|---|---|---|
| skin taxels | 1,992 | 7,968 | 17,928 |
| sensory scalars per frame | 52,981 | 346,406 | 778,054 |
| internal dynamic variables | - | 15,066 | 36,932 |
| episodic store values | - | 137,216 | 405,504 |
| ms per physics step | 1.87 | 2.37 | 3.95 |
| speed (x real time) | 0.54 | 0.42 | 0.25 |

**Targets** for the new tiers (aggregated over all subsystems; only state that is updated by the
dynamics is counted, not padding): `ultra` requires at least 3 million internal state variables and
at least 5 million new sensory/event scalars within 6 s of additional wall time per simulated
second and within 2.5 GB; `mega` requires at least 40 million state variables within 40 s and 8 GB,
for a single instance.  The hardware constraints (i7-14700, 32 GB of RAM of which 5-10 GB is usually
free, a 6 GB graphics processing unit (GPU) that LM Studio already occupies, and numpy as the only
library) determine the extent to which these targets are actually attained.  Results are reported
below as they are measured, and no statement in this section constitutes a claim until a benchmark
measurement supports it.

**Status:** the framework, the tools, the conventions and a design pass covering 20 domains exist;
the domain implementations are being developed in waves.  Measured results will be added to this
section as each wave is completed.

**Language-model mind.**  An Absolute Zero Reasoner (`absolute_zero_reasoner-coder-3b`, Q4_K_S,
1.85 GB, 3.1B parameters) is already loaded in LM Studio at `http://localhost:1234`.  Its
OpenAI-compatible endpoint `/v1/completions` was found to operate with the existing
`<think>/<answer>` prompt: a trial prompt produced `walk_to("apple")` together with a short
reasoning trace.  No download was required.  Integrating the model as the live mind and improving
its navigation performance constitute a separate work stream (see `docs/ultra/azr_navigation.md`
once written); the weights of the model are **not** fine-tuned.
